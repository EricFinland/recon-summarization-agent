# Architecture

## Where this fits

```
 synthetic scan file          Group 1 (this repo)              Group 2
 data/scans/*.json   ──►   recon summarization agent   ──►   classification agent
                           output/*.summary.json
                           (schemas/recon_summary.schema.json)
```

Our job ends at a validated JSON file that matches the schema. Group 2 reads
that file; they should never need to read the raw scan.

## Pipeline

Each step is its own module in `src/recon_agent/`, wired together in
`pipeline.py`:

| Step | Module | Input | Output |
|------|--------|-------|--------|
| 1. Load | `loader.py` | scan file path | `ScanResult` |
| 2. Summarize | `summarizer.py` (+ `prompts.py`) | `ScanResult` | `ReconSummary` |
| 3. Validate | `validator.py` | `ReconSummary`, `ScanResult` | list of problems |
| 4. Write | `output.py` | `ReconSummary` | `output/<scan>.summary.json` |

If validation finds any problem, the pipeline stops and nothing is written.

## Design rules

1. **No unsupported information.** Every host, port, service, product,
   version, and OS guess in the output must appear in the input. If the input
   says `null`, the output says `null`. Nothing is inferred.
2. **Deterministic where possible.** Hosts, ports, and counts are copied
   directly from parsed input, not generated by an LLM. The LLM (if used) only
   writes `overview.summary_text` and rewords notes into observations.
3. **Evidence on every observation.** Each observation carries an `evidence`
   path (for example `hosts[0].notes[1]`) so the validator, and Group 2, can
   trace it back to the input.
4. **Nothing silently dropped.** Closed and filtered ports go in
   `other_ports`; hosts that are down are still listed.
5. **Validate before writing.** Output is checked against the JSON schema and
   against the input before it is saved.

## The contract with Group 2

- Schema: `schemas/recon_summary.schema.json`
- Worked example: `schemas/examples/sample_scan_01.summary.json`
  (the expected output for `data/scans/sample_scan_01.json`)
- `schema_version` is bumped on any change, and changes are agreed with
  Group 2 first. `tests/test_contract.py` keeps the schema, example, and
  sample input consistent.

## Open decisions

- Which LLM provider/model to use (or whether summary_text can be templated
  without an LLM at all).
- Input formats beyond JSON (for example Nmap XML or plain-text output).
- How Group 2 receives the file (shared folder, Docker volume, or API).
